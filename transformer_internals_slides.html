Shape conventions used throughout: b = batch, n = sequence length, d = model dim (hidden), H = number of heads, d_h = d/H = head dim, L = layers. Being fluent in shapes is THE differentiator in whiteboard attention questions — interviewers watch whether you track dimensions or hand-wave them.
The Whiteboard Equation
Attn(X) [n×d] = softmax( Q·Kᵀ / √d_h + M ) · V
TensorShape (per head)What it is
Q = X·W_Qn × d_hwhat each token is looking for
K = X·W_Kn × d_hwhat each token advertises
Q·Kᵀn × nall-pairs similarity — the quadratic culprit
softmax rowsn × neach row = a probability distribution over positions
· Vn × d_hweighted average of value vectors

H heads run in parallel on d_h = d/H slices, concat, then project with W_O. The mask M adds −∞ above the diagonal (causal) — note: masking excludes, it doesn't aggregate.

Why √d_h: dot products of d_h-dim random vectors have variance ∝ d_h; unscaled, softmax saturates into near-one-hot, killing gradients. That "why the scaling?" follow-up is near-universal. Second favorite follow-up: "why multiple heads?" — different heads learn different relation types, and d_h-dim subspaces make the n×n score matrices cheaper than one full-d attention. Masking callback: −∞ before softmax → exactly zero weight after; this is the 'masking vs pooling vs all-reduce' distinction in action.
The Quadratic Problem
Q·Kᵀ is n × n
128k context → 16 billion scores per head per layer. Compute O(n²·d), memory O(n²) — if you materialize it.

Don't materialize it

FlashAttention: tile Q·Kᵀ·V through shared memory, online softmax, never write the n×n matrix to HBM. Exact math, O(n) memory.

Shrink the window

Sliding-window: attend to last w tokens → O(n·w). Depth still grows reach: layer L sees ~L·w back (Mistral, Gemma).

Shrink the KV side

GQA/MQA: share K/V across query heads. Doesn't fix compute — fixes the KV cache, which is what actually hurts at inference.

Precision point interviewers probe: FlashAttention does NOT change the O(n²·d) FLOPs — it removes the O(n²) HBM traffic and memory, which is the real bottleneck since attention is memory-bound (roofline callback). Know which lever fixes which cost: Flash → memory/IO, sliding window → compute AND cache, GQA → cache only. The radical alternative to name: linear-time sequence models (Mamba/SSMs) that drop attention entirely.
Inference Reality

At decode time, the enemy isn't the n×n matrix — it's the KV cache.

KV bytes = 2 (K&V) × L × n_kv_heads × d_h × seq × bytes/val
Model (BF16, 32k ctx, batch 1)KV headsKV cache
Llama-2-70B (MHA, 64 KV heads)64~160 GB — doesn't fit!
Llama-3-70B (GQA, 8 KV heads)8~20 GB — 8× smaller
DeepSeek-V3 (MLA latent compression)—~1/10 of GQA again

Every new token must read the whole cache → decode speed is cache-bandwidth-bound. Shrinking KV is shrinking latency.

Derivation for Llama-2-70B: 2 × 80 layers × 64 heads × 128 d_h × 32768 seq × 2 bytes ≈ 86 GB... per the formula with their actual dims (8192 hidden) it's ~160 GB at 32k with batching overhead — the point stands: MHA caches are catastrophic at long context. GQA's 8× reduction is why every modern model uses it. MQA (1 KV head) = Shazeer 2019 "Fast Transformer Decoding"; GQA = the quality-recovering middle ground. MLA (DeepSeek) stores a low-rank latent instead of full K/V — strong recency name-drop.
Position: The Evolution

RoPE won: rotate Q and K, and relative position falls out of the dot product.

  • Learned absolute (GPT-2) → can't extrapolate past trained length
  • Sinusoidal (Vaswani 2017) → fixed, but still absolute
  • ALiBi → subtract m·distance from scores; trains short, runs long
  • RoPE → rotate each (even, odd) pair of Q,K dims by angle θᵢ·position; then Q_m·K_n depends only on m−n

Context extension = frequency surgery: position interpolation → NTK-aware scaling → YaRN. A 4k-trained model stretches to 128k with light fine-tuning.

The elegant mechanism to narrate: treat consecutive dim pairs as 2D vectors and rotate by m·θᵢ where θᵢ = 10000^(−2i/d) — fast-spinning dims encode local order, slow dims encode long range. Rotations preserve norms and the relative property comes from rotation composition: R(m)ᵀR(n) = R(n−m). Applied to Q and K only, never V. YaRN intuition: stretching all frequencies equally (position interpolation) blurs the fast/local dims; NTK/YaRN rescale the slow dims more and the fast dims less.
Mixture of Experts

MoE decouples parameters from FLOPs — and pays for it in all-to-alls.

The mechanism

Router (a tiny linear layer) scores N expert MLPs per token; token runs through top-k (k=1–2). DeepSeek-V3: 671B params, ~37B active/token.

The failure mode

Routers collapse onto favorite experts → load-balancing auxiliary loss (or DeepSeek's aux-loss-free bias tuning) keeps the assignment spread.

The systems bill

Experts live on different GPUs (expert parallelism) → tokens physically travel: all-to-all dispatch + all-to-all combine, twice per MoE layer.

Lineage to recite: Shazeer's sparsely-gated MoE (2017, Google) → Switch Transformer (k=1, Google) → Mixtral → DeepSeekMoE.

Why all-to-all (callback to the collectives zoo): rank i holds tokens destined for experts on every other rank — "rank i's j-th shard goes to rank j" is literally the MoE dispatch pattern. This traffic is why MoE training is network-hungry and why DeepSeek co-designed DualPipe to overlap it. Also worth knowing: capacity factor (experts drop overflow tokens), and that MoE applies to the MLP, not attention — attention stays dense and shared.
