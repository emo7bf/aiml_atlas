The twist to volunteer: LLM pretraining is self-supervised — the data labels itself (predict the next word), which is how "unlabeled internet" became supervised-scale training signal.

Quick-fire definitions to have ready: k-means (alternate assign-to-nearest-centroid / recompute centroids; minimizes within-cluster variance; k chosen by elbow/silhouette), PCA (project onto top eigenvectors of the covariance matrix — directions of max variance). Both are 30-second answers that come up constantly as warm-ups.
The Central Tradeoff
E[error] = bias² + variance + irreducible noise

High bias (underfit)

Model too simple for the truth. Symptom: train AND validation error both high. Fix: more capacity, better features, less regularization.

High variance (overfit)

Model fits the sampling noise. Symptom: train error low, validation error high — the gap is the tell. Fix: more data, regularization, simpler model, ensembling.

Always answer with the diagnosis protocol (learning curves, train/val gap), not just definitions. Modern twist: double descent — past the interpolation point, bigger deep nets can generalize better again. The U-curve is true but not the whole truth.

Double descent (Belkin et al. 2019; Nakkiran et al. for deep nets): test error falls, rises near the interpolation threshold (model just barely fits all training data), then falls AGAIN as overparameterization grows. One sentence of this marks you as current without needing the theory. Related modern vocab: scaling laws are in some sense the "bias side" story — more capacity + more data together.
The Regularization Toolkit

Everything that fights overfitting, sorted by what it actually does.

  • L2 / weight decay — shrinks all weights smoothly (Bayesian view: Gaussian prior)
  • L1 — drives weights to exactly zero → built-in feature selection (Laplace prior)
  • Dropout — randomly zero activations in training; an implicit ensemble of subnetworks
  • Early stopping — halt when validation error turns; implicit regularization for free
  • Data augmentation / more data — attack variance at the source
  • Cross-validation — not a fix, the measurement instrument (k-fold when data is small)

The trap question: label leakage — validation looks great because a feature secretly encodes the answer. Mention it unprompted; it's the sneakiest production bug in ML.

Why L1 gives sparsity and L2 doesn't: the L1 ball has corners on the axes — the loss contour tends to touch at a corner where some coordinates are exactly 0; the L2 ball is round, so weights shrink but rarely hit zero. A hand-drawn diamond-vs-circle sketch is the classic whiteboard answer. Leakage examples to have ready: timestamp-adjacent features, target-derived aggregates computed over the full dataset, train/test split AFTER feature scaling (fit the scaler on train only!).
The Workhorses

Linear and logistic regression: where every probe question starts.

Linear

y = wᵀx + b, squared loss. Closed form (normal equation) or gradient descent at scale. Assumes linearity, independent errors; sensitive to outliers (that's the squared loss talking).

Logistic

p = σ(wᵀx), trained with cross-entropy. Convex → GD finds the global optimum. Outputs calibrated-ish probabilities; decision boundary is still linear. Softmax = its multiclass form = the final layer of every neural classifier.

The probe to expect: "why cross-entropy instead of squared loss for classification?" — squared loss + sigmoid is non-convex and its gradient vanishes exactly when the model is confidently wrong; cross-entropy's gradient is the clean (p − y)·x, large when wrong.

More probes from this slide: "interpret the weights" (log-odds per unit feature for logistic), "what if features are correlated?" (coefficients unstable — ridge helps), "classes imbalanced?" (class weights, threshold tuning, PR curves over ROC). Metrics vocabulary lives here too: precision/recall/F1, ROC-AUC vs PR-AUC (PR for rare positives) — have the one-liner for each.
Build a Tiny Neural Net · Part 1

Before any layers: the features decide most of the outcome.

1 · Split FIRST

Train / validation / test, split before any fitting — including the scaler. Fit StandardScaler on train only, apply to val/test. Scaling leakage is the classic silent bug.

2 · Engineer features

Impute missing values (+ add a "was-missing" flag — missingness is signal). One-hot low-cardinality categoricals; embeddings for high-cardinality ones. Scale numerics — NNs need this (trees don't).

3 · Smallest model that could work

Input → Dense(64, ReLU) → Dropout(0.2) → Dense(1, sigmoid)
Loss: binary cross-entropy (slide 5's loss — the last layer IS logistic regression). Optimizer: Adam, lr 1e-3.

Say the baseline sentence out loud: "I'd run logistic regression first — the NN must beat it to earn its complexity."

Why NNs need scaling and trees don't: gradient descent shares one learning rate across weights, so wildly different feature scales warp the loss surface into a ravine (slow zig-zag convergence); trees only ask "is x > threshold?" — monotone transforms are invisible to them. Embeddings-vs-one-hot threshold: ~15-50 categories. The 'was-missing flag' trick: imputation erases the fact that data was missing, but missingness often correlates with the label (e.g., users who skip the income field).
Build a Tiny Neural Net · Part 2

Diagnose the fit first. Predict second.

Read the learning curves

Plot train & val loss per epoch — this is slide 3 in motion:
both high & flat → underfit: more capacity, more epochs, check features
train ↓ val ↑ (diverging) → overfit: dropout ↑, weight decay, early stopping, more data
val noisy/spiky → lr too high or batch too small

Then — and only then — predict

Restore the best-val-loss checkpoint (early stopping did this for you). model.predict gives probabilities, not decisions: pick the threshold from the use-case (precision@k, cost matrix), check calibration, and evaluate once on the untouched test set — report PR-AUC if classes are imbalanced.

The order is the answer: fit → diagnose → adjust → freeze → predict → evaluate once. Touching the test set twice is the interview foul.

The diagnostic loop IS the bias-variance slide operationalized — say that connection out loud. Worked rhythm to narrate: "train 20 epochs, see val diverge at epoch 8 → add dropout 0.3 + early stopping patience 3 → curves now track → freeze at best checkpoint → threshold chosen at precision 0.8 because retention outreach costs $5/user → single test-set evaluation: PR-AUC 0.41 vs logistic baseline 0.35 — ship the NN." Thirty seconds, demonstrates the entire discipline. Keras/PyTorch detail on tap: model.fit(validation_data=...) + EarlyStopping(restore_best_weights=True) is the whole part-2 in two lines.
Trees & Ensembles

Bagging cuts variance. Boosting cuts bias. That's the exam answer.

One tree

Greedy splits maximizing purity gain (Gini / entropy). Interpretable, no scaling needed, handles mixed types — and overfits catastrophically if unpruned (high variance).

Bagging → Random Forest

Many deep trees on bootstrap samples (+ random feature subsets), averaged. Averaging independent-ish high-variance models slashes variance.

Boosting → XGBoost

Shallow trees added sequentially, each fitting the previous ensemble's residuals. Reduces bias step by step. The reigning king of tabular data.

The production fact worth stating plainly: gradient-boosted trees still beat deep learning on most tabular problems. Knowing when not to use a neural net is senior signal.

Mapping ensembles onto bias-variance axes closes the loop with slide 3 — say it explicitly. Extra depth on tap: random forests' feature subsampling decorrelates the trees (otherwise all trees pick the same strong feature and averaging helps less); boosting's learning rate = shrinkage per tree; XGBoost adds second-order gradients + clever regularization. OOB (out-of-bag) error = free validation for bagging.
SVMs

Maximize the margin; let the kernel do the feature engineering.

  • Max margin: choose the hyperplane farthest from the nearest points — only those support vectors define the boundary; everything else could vanish without changing it
  • Soft margin (C): tolerate violations; C trades margin width vs training accuracy — it's the bias-variance knob
  • Kernel trick: the dual optimization touches data only via dot products x·x′ → swap in k(x, x′) and you've implicitly mapped to a huge feature space without computing it. RBF = infinite-dimensional
  • Why they faded: ~O(n²) training; past ~10⁵ samples, GBDTs and nets win — but hinge loss and margins live on in modern losses
"Only support vectors matter" has a modern echo worth making: it's a sparsity-of-influence idea. The kernel trick's one-line essence: linear method + nonlinear feature map, paid for only through pairwise similarities. If asked to compare LR vs SVM: LR gives probabilities and scales; SVM gives margins and kernels; with few samples + many dims, SVMs historically shone (genomics-era lore).
Deep Learning (Per the Guide: CNNs & RNNs)

Architectures are inductive biases — say what each one assumes.

CNN: "patterns are local & repeat"

Shared sliding filters → translation equivariance, few parameters (3×3 kernel = 9 weights, applied everywhere). Hierarchy: edges → textures → parts. Milestones: AlexNet 2012 (the detonator), ResNet (skip connections fix vanishing gradients).

RNN: "the past summarizes into a state"

h_t = f(h_{t−1}, x_t). Backprop-through-time multiplies Jacobians → vanishing/exploding gradients; LSTMs fix it with additive gated cell states (same trick as ResNet skips!).

The segue that ties your whole ecosystem together: RNNs are sequential — O(n) unparallelizable steps. Attention removed the recurrence, which is why Transformers won the hardware lottery (GPU deck, slide 1). Full circle.

If asked "CNN vs ViT": ViTs drop the locality bias and need ~100M+ images to compensate (or heavy augmentation/distillation) — inductive bias is a data-efficiency subsidy. If asked "would you ever use an RNN today?": streaming/low-latency regimes, tiny-device inference, and note Mamba/SSMs as recurrence reborn in parallelizable form — shows you track the pendulum. ResNet-LSTM parallel: both fight vanishing gradients with additive identity paths; drawing that connection is a favorite 'depth' moment.

The One-Breath Answer

"Error decomposes into bias plus variance — capacity trades one for the other, diagnosed by the train/validation gap and treated with the regularization toolkit; linear models are the convex, interpretable baseline, bagging averages variance away while boosting chips at bias, SVMs buy nonlinearity through kernels, and deep architectures are just inductive biases — convolution assumes locality, recurrence assumes summarizable pasts — until attention traded those assumptions for parallelism."
