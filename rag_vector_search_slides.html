Debugging heuristic: trace failures backwards. Bad answer? Check what was retrieved. Bad retrieval? Check how it was chunked. Most "the LLM hallucinated" bugs are stage-1 and stage-4 bugs wearing a costume.

The "trace backwards" line is a genuinely useful interview differentiator — it shows debugging methodology, not just architecture recall. Also name the eval per stage: retrieval gets recall@k/MRR against a labeled set; generation gets faithfulness/groundedness (does the answer cite the context?) — two different test harnesses.
Retrieval Stage

Dense finds meaning. Sparse finds the part number.

Dense (embeddings + ANN)

Semantic match: synonyms, paraphrase, concepts. Fails embarrassingly on exact identifiers — SKUs, error codes, proper nouns, version numbers — which get squashed in embedding space.

Sparse (BM25 / TF-IDF)

Exact lexical match in an inverted index. Bulletproof on rare terms; blind to meaning ("car" ≠ "automobile").

Hybrid + RRF

Run both, fuse with Reciprocal Rank Fusion: score = Σ 1/(k + rank). Rank-based, so no score-scale calibration needed. The production default.

The example to deploy: query "ERR_QUIC_PROTOCOL_ERROR site:docs" — dense embedding of that string is mush; BM25 nails it. Conversely "my connection keeps dropping on video calls" needs dense. RRF detail: k≈60 conventionally; being rank-based it gracefully fuses incomparable score distributions. Learned-sparse middle ground: SPLADE (neural term weighting in an inverted index).
Index Internals

Graph, clusters, or quantization-first: know one sentence about each.

IndexMechanismTrade-off
HNSWmulti-layer proximity graph; greedy descent from sparse top to dense base (skip-list logic)best recall/latency, no training; RAM-hungry, awkward deletes
IVF-PQcluster space (coarse), product-quantize residuals to bytestiny memory; lossy, needs training pass
ScaNNpartitions + anisotropic quantization + SIMD scoringthe Google answer; ranking-aware compression
DiskANNSSD-resident graphbillion-scale on one box; latency in ms not µs

The anisotropic insight in one line: standard PQ minimizes reconstruction error; retrieval only cares about errors that flip rankings — so penalize the direction that does.

Which to pick: HNSW for <100M vectors and RAM to burn (every vector DB's default); IVF-PQ/ScaNN when memory dominates cost; DiskANN at billion-scale on a budget. And the recurring judgment check from the RecSys deck: under ~1M vectors, brute force on GPU and skip the index entirely.
The Relevance-Model Spectrum

One axis: how late do query and document interact?

Bi-encoderone vector each; dot product. Indexable, fastest, coarsest.µs · retrieval stage
→
ColBERT (late interaction)vector per TOKEN; MaxSim: each query token takes its best doc-token match. Precomputable AND fine-grained.ms · ~100× storage
→
Cross-encoderquery+doc jointly through full attention. Catches negation & nuance; nothing precomputable.10s of ms × N docs · rerank only

Earlier interaction = more accuracy = less precomputation. The funnel assigns each model where its cost is affordable: bi-encoder on 10⁸, ColBERT on 10⁴, cross-encoder on 10².

"Late interaction" decoded: bi-encoders interact at the very end (one dot product), cross-encoders from layer 1 (full attention), ColBERT in between — token embeddings precomputed independently, interaction deferred to a cheap MaxSim at query time. Why cross-encoders win on nuance: a single vector can't represent "covers X but NOT Y" — negation needs cross-attention. This spectrum slide answers the "why not just use the best model everywhere?" follow-up: cost-per-item × items, the funnel argument again.
The Unglamorous 80%

Chunking is where RAG quality is actually decided.

  • Strategies: fixed-size + overlap (baseline) → recursive-character (respect structure) → semantic/layout-aware (headings, tables) — pick by document type
  • Embed small, return big: parent-document retrieval — match on focused chunks, hand the LLM the surrounding section
  • Metadata filters: date, source, access level — pre-filter before ANN, don't post-filter after
  • Staleness: source doc changes → its chunks must be re-embedded and old vectors invalidated — the RAG twin of the ANN freshness problem from the RecSys deck
Garbage-in-garbage-out is the slide's thesis: a perfect LLM reading a chunk that splits a table from its header will hallucinate confidently. Chunk-size intuition: too small = context-free fragments, too big = diluted embeddings (one vector averaging many topics). 300–800 tokens with 10-20% overlap is the boring-but-right starting answer; layout-aware for PDFs/tables. Version skew callback: embedding-model upgrades require re-embedding the whole corpus — same atomic-swap discipline as the two-tower index.
When Retrieval Fails Anyway

Grade the context. Correct the query. Critique the answer.

Self-RAG / CRAG

An evaluator grades retrieved chunks: relevant → generate · ambiguous → augment (web search) · wrong → re-retrieve. Then the output is critiqued against sources before returning. Retrieval becomes a loop, not a lookup.

Query-side fixes

Query rewriting (decompose multi-hop questions), HyDE (embed a hypothetical answer instead of the question), multi-query expansion. Cheap to mention, often the biggest practical win.

System-design framing: these are fault-tolerance patterns — retries, validation, fallbacks — applied to retrieval. Google interviewers hear "graceful degradation" and smile.

Trade-off to volunteer: every agentic hop adds an LLM call → latency and cost multiply; production systems gate the loop (only re-retrieve when the evaluator's confidence is low) — the same p99-protection instinct as the serving deck. GraphRAG is the index-side alternative: extract entities/relations at ingest so multi-hop questions become graph walks instead of iterative retrieval.

The One-Breath Answer

"RAG is the retrieval funnel feeding a generator: layout-aware chunks embedded into a hybrid index — dense ANN like HNSW or ScaNN fused with BM25 via RRF — reranked by a cross-encoder down to a handful of chunks, with agentic grading and query rewriting as the fault-tolerance layer, and quality owned mostly by the unglamorous stages: chunking, freshness, and stage-separated evals."
